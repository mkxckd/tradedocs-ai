# TradeDocs AI

An evidence-grounded RAG assistant for fictional TradeFlow support and trading-operations documentation.

## Problem and solution

Operational answers in trading must be auditable: a plausible unsupported answer can be worse than no answer. TradeDocs AI retrieves versioned documentation and incident reports, reranks evidence, and responds only when it can point to retrieved sources. Unsupported questions receive an explicit insufficient-evidence response.

## Architecture

```text
Query → intent/rewrite → dense + BM25 candidates → RRF fusion → rerank
      → version-aware evidence → grounded response → citation validation → telemetry
```

The deliberately small implementation keeps the retrieval stages inspectable in `backend/app/main.py`, with SQLite telemetry in `backend/app/storage.py` and a swappable generation interface in `backend/app/generation.py`. It uses 52 fictional, versioned documents, requires no proprietary material, and needs no model key to demo locally.

## Demo and API

Run `uvicorn app.main:app --app-dir backend --reload`, then open `http://localhost:8000`. Try “Why am I getting a 429 error?” or “Compare current API rate limits with previous version.” The answer cites source cards; v3.2 data is not silently mixed with v2.1.

`GET /health`, `POST /chat`, `POST /search`, `GET /documents`, `GET /documents/{id}`, `POST /feedback`, `GET /metrics`, and `GET /conversations/{id}` use Pydantic validation and thin route handlers.

## Retrieval, evaluation, and telemetry

- BM25 and a separate overlap-based dense scorer are fused using reciprocal-rank fusion; `hybrid_rerank` applies a title/entity rerank signal.
- The labeled evaluation data contains 50 cases spanning straightforward, version-conflict, ambiguous, incident, distractor, and insufficient-evidence behavior. `python scripts/evaluate.py` calculates dense, BM25, hybrid, and hybrid+rereank results and writes `data/evaluation/results.json`; values are calculated at run time and are not pre-claimed here.
- Each chat request captures a request ID, detected intent, rewritten query, retrieval timing, retrieved IDs, citations, and refusal state. Telemetry and feedback are persisted locally in SQLite; aggregate data appears at `/metrics` and `/dashboard.html`.

### Measured evaluation result

The latest local run used all 50 labeled cases. Hybrid + reranking achieved Recall@5 **95.6%** and MRR **0.842**, compared with dense-only Recall@5 **93.3%** / MRR **0.814** and BM25 Recall@5 **93.3%** / MRR **0.808**. Citation precision and groundedness were **97.8%**; insufficient-evidence recall was **100%**. These values come from `data/evaluation/results.json`, generated by the evaluator on 2026-09-20.

## Setup

```bash
python -m pip install -r requirements.txt
uvicorn app.main:app --app-dir backend --reload
pytest backend/test_main.py
python scripts/evaluate.py
docker compose up --build
```

## Limitations

This is a portfolio MVP, not a production-readiness claim. It keeps retrieval deterministic and in memory for reproducible demos. A production version would use sentence-transformer embeddings and a cross-encoder reranker, integrate a configured LLM with timeout/retry behavior, and run the same evaluation against a larger, independently reviewed dataset.
